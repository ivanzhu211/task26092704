# avail — 滚动窗口可用性统计库

面向内网监控平台的 Go + SQLite 统计库。探测引擎产生的样本
`{monitorID, at, ok, latencyMs}` 可以乱序、迟到（数天）、重复到达；
`Record` 写入后立即对 `Stats` 可见，无需任何定期全量重建。

## 接口

- `Open(path)` / `Close()`：全部状态持久化在 SQLite，重开后结果不变。
- `Record(Sample)`：写入一个样本；`(monitorID, at)` 去重，代价为 O(log n)，
  不随该监控项历史总量增长。
- `Stats(monitorID, window, now)`：`window ∈ {24h, 7d, 30d}`，统计区间精确为
  `[now−W, now)`，`now` 任意毫秒值，不对齐到任何粒度。无数据的指标返回 nil。

## 设计

- **原始样本表** `samples`：主键 `(monitor_id, at)`，`INSERT OR IGNORE` 去重。
- **小时桶聚合表** `buckets`：每桶保存首尾样本时间、末样本状态、
  桶内首样本之后的 ok 时长（`ok_tail`）、ok 样本数、ok 延迟和、
  以及一个稀疏对数直方图（bin 相对宽度 ≤ 1%，整数边界）。
  桶只是预聚合手段，查询窗口绝不按桶取整。
- **Record**：定位样本所在桶，按"新首样本 / 新末样本 / 插入中间（查前后
  邻居各一次）"三种情况增量更新桶聚合，只动这一行桶记录。
- **Stats**：窗口两端的不完整桶（至多 2 个）直接读原始样本精确计算；
  中间完整桶（包括无样本的空桶）全部由聚合行按 carry 状态推进。
  - 可用率按时间加权：状态由 `at ≤ t` 的最后一个样本决定，逐段积分，
    精确；首个样本之前不计入有状态时长。
  - 平均延迟：桶内 `ok_latency_sum / ok_count` 精确求和。
  - p95：合并各桶直方图后取 nearest-rank 所在 bin 的下界，
    保证 `|v−q| ≤ 1%·q`，对双峰等任意分布成立（不是分段 p95 的拼接）。

## 原始行读取上界

`Stats` 只从样本表读：1 行 carry 查找 + 窗口两端至多 2 个不完整桶内的
原始样本。按探测最小间隔 30s（每小时 ≤ 120 个样本），声明上界
`MaxRawRowsPerStats = 2×120 + 1 = 241`，与窗口长度、窗口内样本数无关。
返回值中的 `RawRowsRead` 报告本次实际读取行数。

## 测试

`go test ./...`：随机化对照测试以直接遍历原始样本的暴力实现为参照，
覆盖数小时退避空档、乱序与重复投递、落在相隔一天以上两样本之间的
迟到样本、p95 恰在跳变点的双峰分布、不对齐的 `now`，对三个窗口逐一
比对可用率/平均延迟（浮点舍入范围内一致）与 p95（误差界内），并校验
`RawRowsRead ≤ MaxRawRowsPerStats`；另含关闭重开后结果不变的对照。
